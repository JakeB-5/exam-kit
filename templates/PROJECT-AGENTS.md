# 프로젝트 AGENTS.md 작성 틀

설치자가 question.md와 지정 자료를 읽고 아래 질문에 답한 **과제 전용 지침**을 작성한다. 이 틀 자체를 프로젝트 AGENTS.md로 복사하지 않는다. 확인된 사실만 쓰며 미정인 실행 명령/경로를 만들지 않는다.

| 루트에 담을 내용 | 작성 기준 |
|---|---|
| 제목·목적·성공 기준 | 실제 프로젝트명, 해결할 업무 문제, 관찰 가능한 성공 행동 |
| 자료와 읽기 순서 | 원문/정책/명세/계획의 실제 링크와 충돌 시 기준 |
| 첫 버전·제외 범위 | 구현할 사용자 흐름과 이번에 하지 않을 기능 |
| 반드시 지킬 동작 | 업무 정책, 데이터/상태 보존, 오류 경로 등 핵심 제약 |
| 현재 구조·개발 순서 | 실제로 있는 파일·모듈과 다음 구현 단위 |
| 실행·검증 | 실제 확인한 앱 명령, 또는 미정 상태와 결정할 단계 |
| 미확정 사항 | 확정이 필요한 내용과 그 전에도 진행 가능한 범위 |
| 완료 기준 | REQ별 방법/실제 결과/증거/미확인, 검토 자료 작성·제안 |

루트에는 설치 명령, SDD 기능 목록, 도구 사용 예시, init 관리 블록을 넣지 않는다. 상세 절차는 프로젝트 안의 `docs/development-workflow.md`로 연결하고 **언제 읽을지** 적는다.

루트에 짧게 유지할 공통 행동:

- 원문과 업무 정책을 우선하며 설계 제안과 확정 요구사항을 구분한다.
- 요구사항 ID를 유지하고 해당 동작의 정상·실패·상태 보존을 검증한다.
- docs/verification.md에 테스트 방법·실제 결과·증거·미확인 사항을 기록한다. 실제 서비스/AI와 mock을 구분한다.
- 구현 범위를 마치면 실제 실행 사례와 미확인 사항으로 docs/review-request.md를 준비하고 담당자 검토를 제안한다.
- 외부 전송·공개 배포·Git 게시를 자동 실행하지 않는다. 설치 중 Playwright 실제 검증을 하지 않는다.

기존 사용자가 작성한 프로젝트 규칙은 길이를 줄이기 위해 삭제하지 않는다. 프로젝트 지침의 품질은 내용과 판단 가능성으로 확인하며 줄 수를 채우지 않는다.
